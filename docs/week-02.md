## 4. 두 조의 결과 비교

작업이 끝나면 두 조가 만든 코드를 나란히 놓고 함께 답하세요.

**4-1. 두 결과의 가장 큰 차이는 무엇입니까?**

```
검색 결과의 사용자 범위 제한 여부이다.
A조는 제목과 본문에서 키워드로 검색이라는 기능 자체를 구현했지만, 누구의 메모를 검색해야 하는지에 대한 정보가 주어지지 않아 SQL에 user_id 조건이 빠졌다.
B조는 본인의 메모만 반환한다는 종료조건과 기존 코드, 스키마를 함께 제공했기 때문에 검색 조건에 user_id를 포함하여 현재 사용자의 메모만 검색하도록 구현했다.
```

**4-2. A조의 실패는 모델 탓입니까, 우리가 주지 않은 탓입니까? 근거를 들어 적으세요.**

```
A조의 실패는 모델 자체의 문제라기보다는 우리가 충분한 조건과 정보를 제공하지 않았기 때문이라고 생각한다. 단순히 메모 검색 기능을 만들어 달라는 핵심 내용만 전달했기 때문에, 구현 과정에서 발생할 수 있는 여러 예외 상황이나 세부적인 동작 방식은 모델이 스스로 판단해야 했고, 그 결과 의도했던 기능과 실제로 만들어진 결과 사이에 차이가 발생했다.
```

**4-3. B조가 준 자료 중 결과를 가장 크게 바꾼 것 하나를 꼽는다면 무엇입니까? 왜 그렇게 생각합니까?**

```
종료 조건이 '본인의 메모만 반환한다.'는 항목이다.
A조와 B조 모두 검색 기능 자체는 만들 수 있었고, 없는 함수나 칼럼을 지어낸 문제도 없었다.
실제 결과가 갈라놓은 핵심은 SQL에 user_id 조건이 포함되었는지 여부였다.
'본인의 메모만 반환한다.'는 종료조건은 검색 기능의 완료 기준에 사용자 범위 제한을 포함 시킨다.
에이전트가 단순히 제목, 본문의 LIKE 검색만 구현하고 끝내지 않고, 현재 사용자 ID를 함께 조건으로 사용해야 한다는 사실을 확인할 수 있다.
```
